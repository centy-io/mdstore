# Race condition on display number assignment during concurrent creates

In storage.rs, get_next_display_number reads all files and then the caller writes the new item. Two concurrent create calls could get the same display number. The reconciliation system handles this after the fact, but a lock or atomic approach could prevent conflicts upfront.
