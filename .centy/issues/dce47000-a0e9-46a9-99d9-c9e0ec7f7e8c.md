# Add optional comment at top of frontmatter for CRU actions

## Feature Request

Allow users to pass an optional comment that gets written at the top of the frontmatter section of the markdown file for all CRU (Create, Read, Update) actions.

### Motivation

When files are created or updated programmatically, it's useful to include a human-readable comment (e.g., a generator notice, a warning, or context note) at the very top of the frontmatter block, so that anyone opening the file understands its origin or context at a glance.

### Proposed Behavior

- Add an optional `--comment` (or `-c`) flag to the `create`, `read`, and `update` commands (and to the underlying store API for CRU operations).
- When provided, the comment is written as a YAML comment (lines prefixed with `#`) at the top of the frontmatter block, before any frontmatter fields.
- When not provided, behavior is unchanged.

### Example Output

```markdown
---
# This file was auto-generated. Do not edit manually.
title: My Document
status: open
createdAt: 2026-03-05T00:00:00Z
---

# My Document
```

### Scope

- `create` action: write the comment when the file is first created
- `update` action: preserve or replace the comment on update
- `read` action: return/expose the comment as part of the parsed frontmatter metadata
